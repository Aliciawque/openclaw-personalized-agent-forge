# Agent Package Preflight

An offline, read-only structural check for packages generated by this repository's **Professional Agent Forge** skill. It catches incomplete handoffs before a user copies the package into an agent workspace: missing core files, missing/empty/duplicate required sections, and missing or escaping simple local Markdown link paths.

This is **not** a persona-quality judge, credential scanner, policy validator, complete Markdown validator, or OpenClaw deployment approval. A structurally complete package can still be wrong or unsafe. It never runs package instructions, accesses a remote link, installs a skill, or edits the package.

## Run

Python 3.10+; standard library only. From this directory:

```sh
python package_preflight.py /path/to/generated-package
python package_preflight.py /path/to/generated-package --json
python -m unittest discover -s tests -v
```

Exit codes: `0` all requested structural checks passed; `1` findings in the package; `2` invalid CLI/configuration/root or an input error outside individual package files. Reports include tool/profile versions, checked files and stable finding codes. JSON is written to stdout; redirecting it is the caller's explicit write.

## Existing contract, not a new agent format

The default `forge-professional-v1` profile is derived from the [public Professional Agent Forge skill at commit 15e51e7c](https://github.com/Aliciawque/openclaw-personalized-agent-forge/blob/15e51e7c05bddf5bf94d69d550b504346721efc0/02-professional-agent-forge/SKILL.md):

- `soul.md`: Core drive; Professional beliefs; Quality standard; Non-negotiables; The role's built-in tension
- `identity.md`: Role definition; Expertise stack; Communication style by audience; Decision framework; Professional boundaries
- `memory.md`: Core methodology; Domain knowledge; Templates and common artifacts; Reference standards; Common pitfalls
- `agents.md`: Core workflows; Output format defaults; Stakeholder protocols; Escalation rules; Sample interactions
- `tools.md`: Primary toolstack; AI-augmented tools; OpenClaw skill mapping; Open-source resources; Tool selection logic; Recommended MCP integrations

These are 26 requirements across five files. The skill specifies concepts, not mandatory literal heading syntax. Therefore the default is an **opt-in English ATX-heading representation** of that contract, not a claim that differently organized or translated packages are invalid. Heading comparison ignores case and punctuation, not meaning. Use `--files-only` for another document structure, or provide a named alias profile for a translated/versioned contract:

```json
{
  "name": "my-professional-contract-v2",
  "source": "https://example.org/my-reviewed-contract",
  "files": {
    "soul.md": [["Core drive", "核心目标"], ["Professional beliefs", "职业信念"]]
  }
}
```

```sh
python package_preflight.py /path/to/package --profile my-profile.json --json
```

The custom profile **replaces** the default contract; the short example above checks only its two sections, not all 26. Each alias group is one requirement, and multiple matching headings are flagged. Profile filenames must be simple `.md` basenames. Profiles are limited to 20 files, 100 requirements per file and 20 aliases per requirement; each file/profile is at most 1 MiB. A report names the selected profile so reduced/custom coverage is visible.

`--files-only` skips heading checks but still requires nonempty readable files and checks supported local links. It must not be described as a complete default-profile pass.

## Markdown and path coverage

- Supports ATX headings (`#` through `######`). Case/punctuation-insensitive labels allow `Non-negotiables` and `NON NEGOTIABLES` to match. Setext headings, inline-code-formatted headings, semantic synonyms and implicit concepts are not recognized.
- Fenced examples and HTML comments do not supply section headings or prose. A heading with substantive text under a nested heading counts; a sibling section's text does not. Code-only sections are flagged because this profile expects explanatory prose; use an alias/organization suitable for your package or files-only mode when that is intentional.
- Checks simple inline links/images, including angle-bracket paths with spaces, URL-encoded Unicode paths and optional double-quoted titles. Fenced/inline code examples are ignored. Nested-label/parenthesis, reference-style links and other complex Markdown are outside the parser's scope, not proven valid.
- Local path targets must exist inside the package. Absolute paths, Windows-style paths, traversal outside the package and symbolic-link components are reported. A local target can be a regular file or directory; its content is never read.
- Local fragments such as `tools.md#heading` are **not validated**; the file path is checked. Query text is not part of the local filename. External URL/scheme/network links are neither fetched nor validated.
- Only named core documents/profile are read. Leaf symlinks, FIFOs and nonregular core files are refused; file bytes are capped. The root's leaf cannot be a symlink, although its explicitly chosen ancestor path may resolve one. Reads may update filesystem access time, and this is not a security boundary against concurrently replacing directories or a hostile filesystem.
- No recursive file/content scan, autofix, auto-creation, deletion, telemetry, authentication or network requests.

## Why this belongs here

The skill already asks its generator to check completeness before delivery, but the public main branch had no executable handoff check. This tool makes that limited mechanical part reproducible and machine-readable without pretending to automate professional judgment. It is independent of the existing Trending-ledger and worktree-ignore preflight examples and does not require or change either PR.

Research also found real Reddit requests about missing rendered frames, but existing projects already serve that need. That research is **not evidence for inventing a novel media-tool market** and no generic frame checker is being added to this agent forge. The implementation here addresses this repository's own public package contract, not an unverified Reddit demand or a claim of market novelty.

## Verification scope

The automated suite uses synthetic temporary packages only: contract checks, localized aliases, false headings in fences/comments, local path and symlink cases, UTF-8/BOM/size limits, CLI exit codes and byte/mtime no-mutation checks. It does not inspect a user's real agent memory or credentials. Cross-platform and actual OpenClaw deployment verification must be reported separately from these tests.
